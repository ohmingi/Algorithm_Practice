## 백준 2805번 나무 자르기 (C++)

이번에 풀어본 문제는 **백준 2805번 나무 자르기**이다.

문제는 아래 링크에서 확인할 수 있다.  
[https://www.acmicpc.net/problem/2805](https://www.acmicpc.net/problem/2805)

### 💻 코드

```
#include <iostream>
#include <vector>

using namespace std;

int ans;

void binary_search(int mid, int left, int right, vector<int> &v, int m){
    if(left > right){
        cout << ans << endl;
        return;
    } 

    long long cnt = 0;
    for(int i = 0; i < v.size(); i++){
        if(v[i] > mid){
            cnt += v[i] - mid;
        }
    }

    if(cnt >= m){
        ans = mid;
        left = mid + 1;
        mid = (left + right) / 2;
        binary_search(mid, left, right, v, m);
    }

    if(cnt < m){
        right = mid - 1;
        mid = (left + right) / 2;
        binary_search(mid, left, right, v, m);
    }
}

int main(){
    int n,m;
    cin >> n >> m;

    int Max = 0;

    vector<int> v;

    for(int i = 0; i < n; i++){
        int a;
        cin >> a;
        v.push_back(a);

        if(a > Max) Max = a;
    }

    int mid = Max / 2;

    binary_search(mid, 0, Max, v, m);
}
```

### 🔍 로직 설명

처음 보면 max에서 시작해서 0으로 가면서 일일히 가면서 탐색을 해야하나? 라는 생각을 가졌다.

근데 주어질 높이의 값이 너무 크기에 최대 log(h) = 1,000,000,000 이기에 1초를 넘어가게 된다.

그렇다면? 다른 알고리즘을 쓰는건지 아니면 탐색을 어떻게 잘해야하는건지 어려운 고민을 이어가게 되었고, 결국 답을 못 찾았다.

그래서 찾아보니 이진탐색을 내가 구현해서 풀면 되는거였다

이문제가 이진탐색을 사용해서 풀기만하면 쉽지만 이진 탐색을 생각해내지 못했던 이유는 내가 이진탐색을 실제로 써서 문제를 풀어본적이 없다! 즉 탐색문제를 제대로 풀어본적이 없다는 말이다  
(내 공부의 깊이에 약점이 있다는것을 또하나 알게됨과 동시에 요즘에 푸는 문제마다 내가 몰랐던 부분을 건드리는 문제들이라서 그건 기분이 좋다. 하나 알게되는것이니까)

어쨌든 가장 큰 높이 max h부터 0까지 그냥 이진탐색 만들어서 돌리면 복잡도는 nlog(H)가 된다
